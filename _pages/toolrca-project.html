01 / THE QUESTION

Abstract.

A study of tool choices, not another RCA framework.

Existing RCA agents often use fixed preprocessing or predefined tools, leaving little experimental guidance on how much analysis tools should do. We define a tool spectrum, compare configurations under shared task and execution conditions, and inspect the decisions that follow tool calls. The contribution is evidence for tool design: what improves, what gets worse, and where useful tool results are lost.

RQ1 / COMPOSITION

More help can mean a worse diagnosis.

With Qwen3.7-Plus, the full toolset improves fault type accuracy over L3, but lowers localization and uses 4.17× the tokens.

RQ2 / CAPABILITY

Calling a tool is not enough.

Models fail at different points: choosing a tool, obtaining a useful result, or assessing its recommendation.

RQ3 / ENVIRONMENT

A useful addition may not transfer.

Adding L2 to L3 helps localization in Online Boutique but hurts it in Sock Shop and Train Ticket.

WHAT CHANGES AFTER THE TOOL RETURNS?

The recommendation is stable. The decision is not.

The first L3 candidate is unchanged in 99.9% of paired trajectories that both obtain a ranking. Additional interfaces change whether the agent keeps that candidate. With L2+L3, correct-to-wrong overrides rise to 9.3% of trajectories, while wrong-to-correct revisions are 3.8%.

07 / DECISION AUDIT

A good recommendation.
An incorrect revision.

The mistake is not seeing an anomaly. It is treating that anomaly as a cause.

Follow the agent's available observations, its interpretation, and a separate reasoning check. The benchmark label is revealed only after the decision. Checks explain the inference; they are not verbatim agent thoughts.

No CPU or memory anomaly does not rule out a delay fault.

A prominent anomaly elsewhere is not enough to replace a candidate. A sound revision needs evidence that supports the new cause and distinguishes it from the old explanation. This does not mean always trusting L3.

Where does a diagnosis fail?

01 / PROCESS

No valid finish.

The agent exhausts the budget or calls an interface without meeting its input requirements.

02 / COVERAGE

The cause never enters.

The investigation does not consider the true root cause.

03 / DECISION

Considered, not chosen.

The agent rejects the correct candidate or confirms an incorrect one.

04 / NAMING

Right entity, wrong type.

A prominent symptom is mistaken for the injected fault.

Section 5.1. For Qwen3.7-Plus with L2 or L3, the true cause was considered in 84–95% of trajectories that nevertheless ended with an incorrect localization. That percentage is conditional on localization failures.
